# 06. BFS (너비 우선 탐색, Breadth-First Search)

## 개념

시작 정점에서 **가까운 정점부터 차례대로** 방문합니다.
물에 돌을 던졌을 때 물결이 퍼지듯, 거리 1인 곳을 모두 방문한 뒤 거리 2인 곳, 그다음 거리 3인 곳… 순서로 넓혀 갑니다.

```
    1
   / \
  2   3        BFS 방문 순서: 1 → 2 → 3 → 4 → 5 → 6
 / \   \       (같은 깊이를 먼저 모두 방문)
4   5   6
```

구현은 **큐**로 합니다.

## 왜 최단 거리가 보장될까?

큐는 먼저 넣은 것을 먼저 꺼내므로, 거리 d인 정점이 모두 처리된 뒤에야 거리 d+1인 정점이 처리됩니다.
따라서 **어떤 정점에 처음 도착한 순간의 거리가 곧 최단 거리**입니다.
(단, 모든 간선의 비용이 같을 때만 성립합니다. 비용이 다르면 → 13 다익스트라)

## 시간복잡도

- 인접 리스트: O(V + E)
- 격자 N×M: O(N × M)

## 언제 쓰나?

- **최단 거리 / 최소 이동 횟수** (미로 탐색, 게임 맵 최단거리)
- 여러 곳에서 동시에 퍼지는 시뮬레이션 (토마토: 시작점 여러 개를 처음부터 큐에 넣음 = 멀티 소스 BFS)
- 단어 변환처럼 "한 번에 한 단계씩 바뀌는" 상태 탐색

## DFS vs BFS 정리

| | DFS | BFS |
|---|---|---|
| 자료구조 | 스택 / 재귀 | 큐 |
| 탐색 순서 | 깊게 먼저 | 넓게(가까운 곳) 먼저 |
| 최단 거리 | ❌ 보장 안 됨 | ✅ 보장 (간선 비용이 같을 때) |
| 잘 맞는 문제 | 연결 요소, 모든 경로, 백트래킹 | 최단 거리, 단계별 확산 |

연결 요소 개수처럼 "방문만 하면 되는" 문제는 둘 다 됩니다.

## 자주 하는 실수

- **큐에서 꺼낼 때가 아니라 큐에 넣을 때 방문 처리**해야 합니다. 꺼낼 때 처리하면 같은 칸이 큐에 여러 번 들어가 메모리/시간 초과가 날 수 있습니다.
- Python에서 `list.pop(0)`, JS에서 `shift()` 사용 → O(N)이라 느림. `deque` / head 인덱스 사용
- 도달할 수 없는 경우(-1 반환)를 처리하지 않음
