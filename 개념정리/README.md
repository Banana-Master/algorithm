## 문제 보고 알고리즘 고르기

| 문제에 이런 표현이 있으면 | 먼저 떠올릴 것 |
|---|---|
| "최단 거리", "최소 이동 횟수" (간선 비용이 모두 같음) | BFS |
| "최소 비용 경로" (간선 비용이 다름) | 다익스트라 |
| "연결된 덩어리 개수", "영역", "섬의 개수" | DFS / BFS |
| "모든 경우", "조합", "순열", N이 아주 작음 (≤ 10) | 완전탐색 / 백트래킹 |
| "경우의 수", "최댓값/최솟값", 같은 계산이 반복됨 | DP |
| "~를 최대로 하려면 매번 ~하면 된다"가 증명됨 | 그리디 |
| N이 매우 큼(10⁹)이고 "조건을 만족하는 최소/최대 값" | 이분 탐색 (파라메트릭 서치) |
| "구간 합" 질문이 여러 번 | 누적합 |
| "연속된 부분 배열", 양수 배열 | 투 포인터 |
| "가장 작은/큰 것을 반복해서 꺼냄" | 힙 |
| "괄호", "짝 맞추기", "직전 값과 비교" | 스택 |
| "순서대로 처리", "대기열" | 큐 |
| "같은 그룹인가?", "사이클이 생기는가?" | 유니온 파인드 |

## 입력 크기로 시간복잡도 짐작하기

보통 **1초에 약 1억(10⁸) 번 연산**이 가능하다고 보고, 입력 크기 N으로 허용되는 복잡도를 거꾸로 추정합니다.
(Python은 C++보다 느리므로 조금 더 보수적으로 잡으세요.)

| N 크기 | 허용 복잡도 | 대표 알고리즘 |
|---|---|---|
| N ≤ 10 | O(N!) | 순열 완전탐색 |
| N ≤ 20 | O(2ᴺ) | 부분집합 완전탐색, 비트마스크 |
| N ≤ 500 | O(N³) | 3중 반복문, 플로이드-워셜 |
| N ≤ 5,000 | O(N²) | 2중 반복문, 기본 DP |
| N ≤ 1,000,000 | O(N log N) | 정렬, 힙, 이분 탐색 |
| N ≤ 10,000,000 | O(N) | 누적합, 투 포인터, 해시 |
| N이 그 이상 | O(log N), O(1) | 이분 탐색, 수학 공식 |
