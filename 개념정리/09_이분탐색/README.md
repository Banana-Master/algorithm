# 09. 이분 탐색 (Binary Search)

## 개념

**정렬된** 범위에서 가운데 값을 확인하고, 답이 있을 수 없는 절반을 버리는 과정을 반복합니다.
범위가 매번 절반으로 줄어서 **O(log N)** 입니다. (10억 개도 약 30번이면 찾습니다.)

```
찾는 값: 7       [1, 3, 5, 7, 9, 11, 13]
1단계: mid=7 → 찾음!
찾는 값: 11      lo=0, hi=6 → mid=3(7)  < 11 → 오른쪽 절반
                 lo=4, hi=6 → mid=5(11) = 11 → 찾음
```

## 두 가지 활용

### 1) 값 찾기
정렬된 배열에서 값의 위치를 찾습니다.
- `lower_bound`: x **이상**이 처음 나오는 위치 (Python `bisect_left`)
- `upper_bound`: x **초과**가 처음 나오는 위치 (Python `bisect_right`)
- x의 개수 = `upper_bound - lower_bound`

### 2) 파라메트릭 서치 (답을 이분 탐색)
"조건을 만족하는 **최솟값/최댓값**"을 구하는 문제를 **"값이 X일 때 조건을 만족하는가? (예/아니오)"** 로 바꿉니다.
X가 커질수록 답이 `아니오 아니오 … 예 예 예`처럼 한 번만 바뀐다면, 그 경계를 이분 탐색으로 찾을 수 있습니다.

- 입국심사: "T분 안에 n명을 모두 심사할 수 있는가?" → 가능한 최소 T
- 나무 자르기: "높이 H로 자르면 M미터 이상 얻는가?" → 가능한 최대 H

> 💡 **답의 범위가 매우 큰데(10⁹ 이상) "최소/최대"를 묻는다면** 파라메트릭 서치를 의심하세요.

## 자주 하는 실수

- 정렬하지 않고 이분 탐색
- `lo <= hi` / `lo < hi`, `mid + 1` / `mid` 를 섞어 써서 무한 루프 → **하나의 템플릿만 외워서 쓰세요** (아래 예제)
- JS에서 `(lo + hi) / 2`는 소수가 됩니다 → `Math.floor((lo + hi) / 2)`
- 답의 범위(lo, hi)를 너무 좁게 잡음 (입국심사에서 hi = 가장 느린 심사관 시간 × n)
